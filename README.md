# SPLITZY 💸
### Good times. Fair shares.

A modern, responsive bill-splitting web app that makes sharing expenses simple, transparent, and accurate.

Built during ZeroCode — Techfest, IIT Bombay (Mumbai Zonals), 4 October 2026, under a 70-minute time constraint using Google AI Studio and vanilla web technologies.

## ✨ Features

- **Equal Split:** Divide a bill equally among participants.
- **Custom Split:** Customize individual shares.
- **Paisa-Exact Calculations:** Keep the split accurate to two decimal places and reconcile the total.
- **Visual Breakdown:** View each participant's share through a donut chart and participant cards.
- **Occasion-Based Bills:** Add a name or occasion to each split.
- **Participant Management:** View and rename participants.
- **Recent Splits:** Access saved split history.
- **UPI Payment Support:** Help participants settle their shares using UPI.
- **Responsive UI:** A polished interface for different screen sizes.
- **Theme Toggle:** Switch between available themes.

## 🛠️ Tech Stack

- **HTML5** — structure
- **CSS3** — styling and responsive layout
- **Vanilla JavaScript** — calculations and interactivity
- **Google AI Studio** — AI-assisted development during the competition

## 🚀 Getting Started

### Run locally

1. Clone the repository:

   ```bash
   git clone https://github.com/Jyoti-Prasad08/splitzy-bill-splitter.git
   ```

2. Open the project folder:

   ```bash
   cd splitzy-bill-splitter
   ```

3. Open `index.html` in your browser, or use VS Code with the Live Server extension.

No framework or package installation is required for the vanilla frontend.

## 💡 Why SPLITZY?

Splitting expenses should not mean awkward calculations or confusion over who owes what. SPLITZY aims to make the process clearer, faster, and easier for everyone involved.

## 🧠 Built at ZeroCode

The challenge was to build a working, interactive frontend in **70 minutes**, with the first five prompts free and additional prompts affecting the score.

Working within those constraints reinforced an important lesson: building with AI is not only about writing prompts. It also requires defining expected behaviour, thinking through edge cases, and communicating requirements clearly.
